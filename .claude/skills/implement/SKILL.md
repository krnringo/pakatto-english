# implement — 実装スキル

仕様書(`docs/specs/{NN-feature}.md`)を、検証可能な単位に分解しながら実装する。

## 手順

### 1. 仕様書を読む

`docs/specs/{NN-feature}.md` の Task breakdown と Verification criteria を確認する。
仕様書がまだ無い/曖昧なら、先に `requirements` スキルに戻る(仕様なしで実装しない)。

### 2. 難易度を判定する

以下に1つでも該当するなら、着手前にグローバルスキル `deep-task`(`~/.claude/skills/deep-task/SKILL.md`)を読む:

- 触るファイルが3つ以上
- 「どこを直すか」より先に「なぜそうなっているか」の調査が要る
- 本番設定・データ移行・外部送信・不可逆操作(削除・force push)を含む
- 過去に一度失敗している領域

該当しなければ、以下の軽量な手順だけで進めてよい。

### 3. 検証可能な単位で実装する

仕様書のTask breakdownに従い、各ステップの完了時に何かを実行・確認できる形で進める。

- 悪い分解: 「モデル作る→API作る→UI作る→最後に動作確認」(検証が最後の1回しかない)
- 良い分解: 「モデル+その場でテスト→APIを1本作りcurlで叩く→残りのAPI→UIをつなぎ画面で確認」

実装前に、既存の似た実装を1つ探して読む(命名・構造・エラー処理の流儀を踏襲する。ゼロから発明しない)。
変更対象の呼び出し元/参照元は先にgrepで洗っておく。

### 4. 各ステップで検証する

「動くはず」で次のステップに進まない。Verification criteriaにあるテストケースを実行し、
結果(pass/fail、実際の出力)を確認してから次に進む。

### 5. 完了条件

仕様書のVerification criteriaが全て満たされたら実装完了。次は `review` スキルに引き継ぐ
(自分の実装を自分でレビューして「完了」と申告しない)。
